# Languages

The mod patches text pointers in the game image. The same technique works for every language that can
be displayed in the Windows-1252 character set of the game fonts. German is the reference language and
is loaded unchanged from `data/german_localization.tsv` and `data/render_translations.tsv`.

## Choosing a language

Put `localization.ini` into the `mods\` folder (next to the DLL) or into the game folder:

```ini
language=fr
```

Codes: `de`, `fr`, `nl`, `es`, `it`, `sv`, `da`, `no`, `pt`. `fr`, `fr-FR` and `FR_fr` are equivalent. An
unknown code aborts the start with a message that lists all available languages. Without the file,
German is used.

| Code | Language   | Status |
|------|------------|--------|
| de   | Deutsch    | complete (reference) |
| fr   | Français   | all slots translated, not proofread |
| nl   | Nederlands | all slots translated, not proofread |
| es   | Español    | all slots translated, not proofread |
| it   | Italiano   | all slots translated, not proofread |
| sv   | Svenska    | all slots translated, not proofread |
| da   | Dansk      | all slots translated, not proofread |
| no   | Norsk      | all slots translated, not proofread |
| pt   | Português  | all slots translated, not proofread |

Untranslated texts stay English. A slot that another mod has already redirected is skipped in the
additional languages. German still aborts with an error message in that case.

## File format `data/lang/<code>.tsv`

Three columns, tab-separated, `#` starts a comment:

| Scope        | Meaning |
|--------------|---------|
| `0x…`        | Text slot in the game image. Column 2 is the English original and must match the slot table exactly. |
| `render`     | Exact text that is translated only when drawn (also from other mods). |
| `addon`      | Like `render`, but only for callers outside the game image (e.g. goods names of a mod). |
| `resource:N` | String resource N. |
| `frag`       | Template for the pattern translators: month names `month.Jan` … `month.Dec`, `report_on`, `report_range`, `chronicle`, `goods_supply`, `town_inhabitants`, `town_information`, `town_population`, `lord_mayor`, `lady_mayoress`, `tavern_sailors`, `pirate_capture`, `pirate_captain`, `manager_stage`, `day_one`, `day_many`. Placeholders in `{…}`. |

Slots come from `data/german_localization.tsv` and `data/extra_slots.tsv` (texts that are identical in
German and English and therefore missing in the German table). Month names contain no space. If a
template is missing, the text concerned stays English.

For every embedded language, `cargo test` checks: valid slot, English original matches, `%`
placeholders, backslash markup, line breaks and edge spaces unchanged, characters representable in
Windows-1252, templates complete, render table buildable.

## Game file texts (`data/files/<code>.tsv`)

Missions, maps, ini files and name lists are not part of the game image. The game reads them through
`archiver.dll`, in one of two ways (`arc_CreateFile` for missions and ini files, `arc_CreateMemMapped` for
maps and name lists). Both hooks hand the file to the same function, which replaces the texts of the
English original and gives the game the result from memory (`src/files/`). Files that do not match the
English originals, for example loose replacement files, reach the game unchanged.

`FILES` in `src/files/mod.rs` lists every game file with texts and its format:

| Scope (column 1) | File | Format |
|---|---|---|
| `*.p2m` | every mission script | Column 2 is the English text in the mission codec: `\n` = line break, `\t`, `\\`, `\xHH`, `{%X:HH}` = format token `%X` with argument byte `HH`. The translation must keep the tokens. |
| `<name>.p2m` | one mission (file name without folder) | Like `*.p2m`, wins over it; for a sentence that reads differently in one mission. The tokens are not compared. |
| `*.gmf` | maps | The 40 town names. They appear on the sea chart, in the title bar and in every text that names a town through a placeholder. |
| `scripts/missions_eng.ini`, `tutorial_eng.ini`, `credits_eng.ini`, `stadtauswahl.ini` | ini files | Whole `key=value` values; tutorial markup (`\\f0_`, `\\f1_`, `\n`) and the `|` layout of the credits stay as in English. |
| `scripts/namenstaedte_eng.txt` | town, guild and tavern names (40 each) | One line each. |
| `scripts/namenschiffe_eng.txt`, `namenmaenner.txt`, `namenfrauen.txt`, `namenfamilien.txt` | ship and person names | One line each. The name generator ends a name at every character below `A` except space and `.`, so names must not contain apostrophes, hyphens or digits. |

Column 3 is the translation. `=` keeps the English text; the row `<scope><TAB>*<TAB>=` keeps a whole file
(person names). `#` starts a comment.

`data/files/source.tsv` lists every English text of these files and is generated by
`tools/textkit/extract.py` from the extracted English archives. Each table must decide on every text: a
translation, `=` or a `*` row. `cargo test` reports the coverage per file and language and checks that every
row refers to an English text, that the rows decode, that tokens, font limits (see below, except for German)
and name rules are kept, and that every text uses the town names of `data/glossary/towns.tsv`.

Town names follow the form customary in the language (`Londres`, `Keulen`, `Dantzig`, German `Köln`,
`Danzig`, `Thorn` as in the German game). `tools/textkit/glossary.py <code>` applies the glossary to a table
and writes its map and town-list rows; `tools/textkit/glyphs.py` replaces characters the font cannot draw.

## German and the original Patrizier 2 Gold

Patrician III is the English release of Patrizier II Gold, so the German tables follow the German original
wherever the English release did not change the text. `tools/textkit/p2ref.py <Patrician3.exe> <Patrizier 2.exe>`
aligns the text slots of both executables and reads their string resources by ID; it writes `slots.tsv`
(table row next to the original), `missing.tsv` (slots without a German row whose original differs from
English) and `resources.tsv` to `target/p2ref/`, outside the repository. Deviations from the original are
deliberate where Patrician III passes other or reordered arguments or composes a sentence differently.

Tooltips and button labels are Windows string resources. German translates them by resource ID
(`resource:N` rows in `data/render_translations.tsv`, text as in the original), so a building tooltip such
as `Pottery` (Töpferei) never renames the ware `pottery` (Keramik) or another text of the same spelling.

The abbreviated month names (`Jan` … `Dec`, slots `0x2C0D04`-`0x2C0D30`) are slots in every language. They are
never global render keys, so `May` or `Mar` elsewhere stay untouched.

## What is translated (and what is not)

All text slots of the slot table are filled for fr, nl, es, it, sv, da, no and pt, plus the
templates (`frag`), render and addon texts. That covers menus, labels, names, letters, event and
chronicle texts and the composed sentence fragments. Missions (579 texts), the campaign list
(25 texts), the tutorial (159 texts) and the credits (43 texts) are translated for all languages as well,
as are town names (map), guild, tavern and ship names. Person names (`NamenMaenner`, `NamenFrauen`,
`NamenFamilien`) are historical names and stay as released in every language. German is handled exactly
like every other language: the game stays the English release and only its texts are replaced from
`data/files/de.tsv`; town, guild, tavern and ship names come from the German game.

The main menu, whose eight entries are painted into its pictures, has its own pictures per language,
German included: `data/gfx/<code>/` holds `Hauptmenu.jpg` (background), `p_hmenu01.bmp` (highlighted
entries, magenta is transparent), `hmenu_colormap.bmp` (click areas, palette index 0-7 per entry) and
`textures.tsv` (the rectangles of the highlighted entries for `scripts/textures.ini`). The release puts them
into `mods\localization\<code>\`; the hook hands them to the game in place of the English pictures. They
are made by `tools/gfx/gen.py` from the English pictures in the archive: the English words are taken out,
the page is rebuilt from the surrounding paper and the words of `WORDS` in `gen.py` are set in Goudy Old
Style Bold along the measured lines of the book, the initials into one clean box (`tools/gfx/box.png`). The
font is not part of the repository; it comes with Windows as `GOUDOSB.TTF`.

Not translated:

- Other pictures with text.
- Texts stored in the start savegames of the tutorial and the scenarios (`missav/*.pat`): a few dozen
  tavern offers and letters per file, which the English release ships in German. The savegame format with
  its length fields has not been analysed yet; changing it blindly would corrupt the saves.

The German texts of the missions were taken from the original German game and paired with the English
scripts string by string. Where the German scripts used other format tokens than the English ones (gender
and case tokens `%g %A %v %r`), the affected letters use the English tokens, because the English scripts
supply those arguments. The campaign list asks for `Kampagne3_Entfuehrung.p2m` while the English archive holds
`Kampagne3_Entführung.p2m`; the hook retries a missing mission under the archive's spelling.

Limits of quality (cannot be verified by machine):

- Fragment chains and gender, case and genitive forms follow the slot structure of the German
  template and are approximations; some sentences read choppily in the game.
- The order of placeholders follows English, even where the target language would order differently.
- No review by native speakers. Loading in the game has been checked for `de`, `nl` and `sv`. For all
  nine languages the campaign selection and the first campaign letter have been run in the game; other
  missions have not. The tutorial has been opened in the game for `de`, `fr`, `sv` and `es`, the credits
  for `fr`, `da`, `no` and `de`; the town names of the map for `fr` and `da`; the other languages are
  checked by `cargo test` only.

## Character set

The game font is a bitmap font that only contains ASCII, `ä ö ü Ä Ö Ü ß` and the lowercase accents
`á à â é è ê í ì î ó ò ô ú ù û` (checked glyph by glyph in the game). Every other character is drawn as
an empty gap, so the translations use these substitutions (a unit test enforces the allowed set):

| Language | Substitution |
|---|---|
| sv | `å` -> `a` |
| da, no | `å` -> `aa`, `æ` -> `ae`, `ø` -> `oe` (accepted digraph spelling) |
| es | `ñ` -> `ni`, `¡` `¿` dropped |
| pt | `ã` -> `a`, `õ` -> `o`, `ç` -> `c` |
| fr | `ç` -> `c`, `ï` -> `i`, `œ` -> `oe`, `« »` -> `"` |
| nl | `ë` -> `e`, `ï` -> `i` |
| it | `È` -> `E'` |
| all | capital accented letters lose the accent (`É` -> `E`), `º ª °` -> `o a o`, typographic quotes and dashes -> ASCII |

New fonts (or a font patch) would be needed for real `å æ ø ñ ç ã õ` glyphs. Not possible without
that: Polish, Czech, Hungarian (partly), Baltic languages, Cyrillic, Greek.

## Style: the Hanseatic Middle Ages

Texts are translated from the point of view of the Hanseatic period (Kontore, town council, guilds,
cogs), not in dictionary or machine style. Guidelines:

1. Historically attested terms of the respective language before modern administrative terms
   (Lord Mayor = bourgmestre / burgemeester / borgmester, not "Maire" or "Mayor").
2. Hanseatic terms without a common equivalent stay in their Hanseatic form
   (Alderman, Kontor, Schnigge, Kraier).
3. The player is addressed in the polite or plural form of the language, not in today's everyday
   address ("vous", "u", "ni", "De").
4. Currencies and measures in the unit of the time (Last, not tonne).
5. Short labels stay short: buttons in the base form, without punctuation.
6. English is authoritative for the meaning; German is only a reference for length and context.

## Adding a new language

1. Create `data/lang/<code>.tsv`: one line `0x…<TAB>English<TAB>translation` per slot; take edge markup
   (`\\c`, `\\f1_`, `\n`) from the English column.
2. Add the `frag` lines for months and pattern translators (see above).
3. Create `data/files/<code>.tsv` with a decision for every text of `data/files/source.tsv` (see above), add
   a column to `data/glossary/towns.tsv` and run `tools/textkit/glossary.py <code>`.
4. Add an entry to `LANGUAGES` in `src/language.rs` using `include_str!` for both tables.
5. Run `cargo test`; then set `language=<code>` in `localization.ini` and check in the game.
6. Add `docs/install/<code>.md` (copy an existing guide) and list the language in `README.md`.
